### [B4XPages][Macro] Introducing B4J2ASync: Synchronizer for Development of B4A apps on the B4J Platform. by William Lancee
### 07/20/2026
[B4X Forum - B4X - Tutorials](https://www.b4x.com/android/forum/threads/171602/)

Many of this community choose to do initial development of Android apps on B4J because  
B4J apps are faster in compilation and execution and B4J apps do not need a connection to an external device or emulator.  
After your App is complete, you'll have a both a Windows/Desktop and an Android/Device implementation.  
Updates can then be done on a single code base.  
  
When you open the standard B4J B4XPages template, you get a default B4J folder and a default B4A folder.  
You start developing a new app in the B4J folder until you are satisfied with its performance.  
When ready try it out in B4A, you must modify the default B4A by including the appropriate modules and libraries.   
You must also open both B4J and B4A Designers and manually copy/paste the contents of all layouts.  
  
I have found these synching steps to be cumbersome and they can lead to (sometimes difficult to find) bugs.  
The helper app/macro 'B4J2ASync' does all of these steps automatically.  
To prevent potential loss of work, B4J2ASync saves the last 10 versions of the B4A folder and contents.  
The date/time stamped backup folders are in the "\SavedB4AFolders" folder in the same place as the \B4A and \B4J folders.  
  
In order to synchronize the .bal layout files with .bjl layout files, the macro needs  
to convert xxx.bjl to xxx.bal. This involves conversion of the .bjl files to .json files. Code is taken from [USER=1]@Erel[/USER] 's balConverter.  
After you have the .json map, converting the bjl.json to bal.json is not an easy task - there are many differences.  
  
After a number of false starts, I created a single layout with all possible native and custom B4J Views.  
Then I created an empty layout in B4A and copy/pasted all of these views into this layout.  
Then I converted both layouts to .json files and studied the differences.  
I knew that if I could do this conversion automatically, and because balConverter code can convert .json back to .bal,  
I would be well on my way to meeting my objective.  
  
After another number of false starts, I found an efficient method.  
Based on the 'all-views' bal==>json file, I created a Schema for B4A layouts - one for each type of B4A view.  
Then going through a particular bjl==>json file, I look up each view's B4A schema and make it conform to that schema.  
This new map then gets converted to bal and we're done.  
  
Not all B4J Views can be converted to B4A Views. The following do not have B4A equivalents:  
Accordion, Canvas, ColorPicker, DatePicker, HTMLEditor, MenuBar, Pagination, SplitPane, TabPane, TableView, TreeTableView, TreeView  
  
All of the CustomViews are cross-platform but depend on XUI View library which (with other libraries) will be synched by B4J2ASync.  
  
Other views require a name change and some other changes:  
Pane => Panel, ProgressIndicator => ProgressBar, ChoiceBox => Spinner, ComboBox => Spinner,   
ScrollPane => ScrollView, Slider => SeekBar, TextArea => EditText, TextField => EditText  
  
B4J2ASync will log what changes it is making and what cannot be converted.  
  
To keep the complex synchronization task from further complexity, I restricted the .bjl to .bal conversion to one variant per layout.  
For each variant you need to design a separate layout anyway - so this is not too restrictive.  
  
B4J2ASync will copy .bjl designer scripts to the .bal file. Take a look at the example layouts.  
  
NB1: B4J2ASync depends on the default folder structure of the cross-platform B4XPages template.  
NB2: Since B4J2ASync modifies the B4A source file, it is critical that the B4A IDE is closed.  
 If it is open, the changes B4J2ASync makes will be over-ridden by the B4A IDE.  
 B4J2ASync will test for an open B4A IDE and tell you to close it first and then try the macro again.  
NB3: Before you can run the macro, you have to copy the attached B4J2ASync.jar to your Additional folder.

The macro is:  
  

```B4X
#if b4j  
#Macro: Title, B4J2A Synchronizer, ide://run?File=%ADDITIONAL%\B4J2ASync.jar&Args=%PROJECT%  
#End If
```
